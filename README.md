# Clive

いつも動いている、あなた専用の AI エージェントです。ブラウザから話しかけて使います。
会話の中で覚えたことを次の会話で活かし、頼まれたことや自分で気になったことを、裏で少しずつ進めます。
Windows と Linux で動き、クラウドの API（Anthropic など）とローカル LLM のどちらでも使えます。

## できること

### 会話

- 返事はストリーミングで表示され、途中で止めたり、失敗したら送り直したりできる。返事の下にはコピーが出る（どのモデルが返したかは、実行ログのモデル列で見る）。道具を使った行（名前・結果の 1 行目・成功か失敗か）は押すと中身が開き、記憶したことは「取り消す」で戻せる（会話の中の行にも、右下の知らせにも出る）
- 入力欄は文章に合わせて伸びる（最大 200px）。Enter で送り、Shift+Enter で改行する（日本語の変換中の Enter は送らない）。「/」で、新しい会話（`/new`）・タスク（`/task` `/tasks`）・スキル・ツール（`/skills`）・実行ログ（`/log`）・記憶（`/memory`）・返事を止める（`/stop`）・会話の題を変える（`/rename 新しい題`）・会話をアーカイブする（`/archive`。確認を挟む）を呼べる。承認待ちのときに空のまま Enter を押すと、表示している札が「今回だけ許可」になる（札が出てから、また画面やウィンドウに戻ってから 1 秒は効かない。連打や見ていない間に出た札を、確かめずに許可しないため）
- 返事を作れなかったときは、理由と直し方、「もう一度送る」を出す。コンテキスト長が足りなくて送る前に止めたときは、実際に使う長さ・必要な長さ・設定値・実測値・モデルの上限を並べ、入力した文は残したまま設定へ案内する。送ったあとで収まらなくなったときは、使える長さと必要な長さを出す
- 使うモデルを複数並べておくと、つながらないときに次のモデルへ自動で切り替える
- 長くなった会話は、古い部分を要約に置き換えて続ける（元の発言は残る）
- テキスト・PDF・画像（画像を読めるモデルのとき）を添付できる
- Clive の返事の言語を日本語か英語から選べる（画面の「設定」›「見た目」か、`config.json` の `language`。下の「[Clive の言語](#clive-の言語日本語英語)」）

### 記憶

- Clive は会話の中で大事なことをその場で覚え、次の会話から使う。覚えたことは、左の一覧の「記憶」で見て、直して、消して、取り消せる（2 冊それぞれの使用量の線、追加・編集・削除・履歴・取り消し、過去の会話の検索。削除するとすぐ「取り消す」のトーストが出る。会話の中の「記憶しました」から取り消した分もここに反映される）。上限は画面の「設定」›「記憶」で変えられる
- 記憶は「ユーザーについて」と「Clive のメモと教訓」の 2 冊に分かれ、それぞれ量に上限がある。いっぱいになりそうなときは、似た記憶をまとめさせる
- 「前に話したあれ」は、過去の会話から探して答える（日本語の 1〜2 文字でも探せる）
- タスクが終わったときや会話が途切れたときに、Clive が記憶を振り返って整える（拾い漏れを足し、重なりをまとめる）。振り返りでは、シェルやファイル、Web は使えない。変えた記憶は、画面の「実行ログ」の「振り返り」で見られる（記憶のページから取り消せる）
- Clive の人格（SOUL.md）とユーザーのプロフィール（USER.md）は手で書ける。Clive が書き換えるときは承認が要る

### タスクと自分で動くこと

- やること（タスク）を、Clive が会話の中で書き留めたり、画面から頼んだりできる。毎日・平日・毎週・毎時・N 分ごとの繰り返しも書ける
- 左の「タスク」の画面は、「あなたの対応が必要」（返事待ちと、Clive からの提案）・「実行中・実行待ち」・「予定」・「完了」の節に分かれる。返事待ちにはその場で答え、提案は承認か見送りができ、実行待ちは「実行」、予定は「今すぐ実行」、実行中は「止める」で動かせる。行を押すと右から詳細が開き、題・詳細・次の一手の直し、結果・経過の記録・この予定から作った実行・Clive の作業記録を見られる。「新しいタスク」（コマンドパレットからも開ける）では、今すぐ・日時・繰り返しを選んで頼める。日時はサーバーのタイムゾーンの時刻で、そばに名前を出す
- 裏で動く「ワーカー」が、タスクを 1 件ずつ進める。終わったら報告し、分からないことがあれば質問して返事を待つ。途中までなら経過を残して、時間をおいて続きをする
- 話しかけると、進めていたタスクを中断して会話を優先し、あとで続きから再開する
- 実行中のタスクを「止める」と、取り消しではなく 20 秒ほど休んで実行待ちに戻り、また動き出す。本当にやめたいときは「取り消す」か、ワーカーの「一時停止」を使う
- Clive を終了したときに実行中だったタスクは、「止める」とは別に扱う。終了の処理（`shutdown()`）は `app.close()` のすぐあとに `process.exit(0)` で止まるため、止められたタスクの 20 秒の待ちは記録されず、タスクは実行中のまま残る。次に起動したときに `recoverExpiredLeases({ all: true })` がすぐ実行待ちに戻し、続きから動く
- やることが無いときは、モデルを呼ばずに休む。失敗は間をおいて試し直し、続けば知らせる
- 自発行動（Clive が自分で決めたタスクや、気になったことを調べること）は、オン／オフ・静かにする時間帯・1 時間あたりの上限で抑えられる。既定はオフ
- 気になっていること（好奇心）は、タスクの画面の一番下の節「気になること」で、一覧・追加・「今すぐ調べてもらう」・やめるができる。古い「好奇心」の画面（`#/curiosity`）のリンクは、この節を開く
- 繰り返し使える手順は「スキル」（手順書）として残せる。画面の「スキル・ツール」で、スキルを開いて直す・新しく書く・消せる。Clive が書いたスキルは「レビュー待ち」として一覧の先頭に出て、開いて内容（直す場合は、いまの内容との見比べ）を確かめ、承認するまで使われない

### 道具と安全

- ファイルの読み書きとシェルの実行ができる。触れてよいフォルダ（読み書き／読むだけ）と触れないパスを決めておき（画面の「スキル・ツール」の「フォルダ」で直せる。範囲を広げる保存は、広がるものを並べて確かめてから保存する）、その外や危ない操作（消す・秘密を読む・外へ送るなど）は、実行の前に止めるか、画面で承認を求める。使える道具の一覧（24 個）は、同じ画面の「道具」で見られる（道具ごとの承認の切り替えは、まだ無い）
- 承認は「今回だけ許可／この会話では許可／拒否」から選ぶ。承認の札は会話の入力欄の上に固定され、残り時間（過ぎると拒否）が減る線で見える。「詳細」で、作業フォルダ・承認が要る理由・見つけたパスを開ける
- シェルの判定はコマンドの文字列を見て止める仕組みで、完全な閉じ込めではない（許可したフォルダにスクリプトを書いてから実行する、などで回り道できる）。守りたいものがある環境では、OS の側でも閉じ込める（Linux は下の systemd の設定、Windows は権限の低い別のユーザーで動かす）
- 実行の前に、自分で用意したコマンドで判定を足せる（下の「[実行前のフック](#実行前のフック)」）
- Web の検索（DuckDuckGo か自分で立てた SearXNG。API キーは要らない）と、公開されているページの読み取りができる。ローカルや LAN の宛先は読まない。Web や添付の内容を読んだ後は、シェルと書き込みが承認制になる
- API キーは設定ファイルにも画面にも出さない

### 見た目と通知

- Clive の名前・形（20 種類）・色・動きを、画面の「設定」›「見た目」で選べる。「自動」にすると、返事を考えている・承認や返事を待っている・お休み中・タスクを終えた、といった様子に合わせて動く
- 画面の「設定」は、左に節（モデルとコンテキスト長・プロバイダ・API キー・道具・ワーカー・記憶・見た目・サーバー・設定ファイル）、右に中身。変えた行と節には点が付き、下の帯に「保存していない変更が N 件」と「元に戻す / 保存する」（⌘/Ctrl+S でも保存）が出る。保存が断られたときは理由が場所つきで出て、押すとその行へ飛ぶ。保存の直前に最新の設定を読み直し、自分が触った所だけを当てる（右のパネルの自発行動の切り替えなど、画面を開いたあとにほかの場所が変えた値は巻き戻さない。触った所をほかの場所も先に変えていたら、何も書かずに「最新を読み込む」を出す）。保存していない編集があるままページを閉じようとすると、ブラウザが確かめる。Clive が触れられる範囲や動かせるものが広がる保存（触れないパスを外す・フォルダを足す・読むだけを読み書きにする・シェルを有効にする・承認なしのコマンドを足す・承認や止めるコマンドから外す・フックを足す／書き換える・外からの入口を足す・プロバイダの送り先をこの PC の外のアドレスにする／使うキーを増やす・Web 検索の送り先を外へ向ける、など。設定ファイルの JSON で直したものも同じ）は、広がるものを並べて確かめてから書く。サーバーの節（ポートなど）を変えたときは、再起動が要ると知らせる。設定ファイルの JSON も、ここで直接直せる
- 画面の「実行ログ」は、すべての実行（種類・モデル・結果・秒数・トークン）と、道具の記録（判定と決めた人・結果）、記憶の振り返りの記録を、新しい順に 200 件まで切り替えて見せる。同じ失敗が続いていないかを確かめるためのもの。実行中の振り返りのリンクを押すと「振り返り」が開く
- 右のパネル「いまの動き」（左上の名前の絵を押すか、⌘/ か Ctrl+/）で、今の様子と件数（承認待ち・返事待ち・未読の通知）、今日終わったこと、ワーカー（自発行動のオン/オフ、一時停止と再開、次に動く時刻、この 1 時間の実行数）、実行中のタスクと経過時間、次に動くタスク、最近の実行をまとめて見られる。幅が 760px 未満の画面では、左のメニューの項目「いまの動き」になる
- 画面の枠は、左に会話とページの一覧、上にタブ（開いている会話だけ。タスクなどのページはタブにならない。閉じても保存される）、下に状態バー（接続・ワーカーの状態と 1 時間の実行数・実行中のタスクと経過時間・承認待ち・使うモデル・未読の通知・ライト/ダークの切り替え）。記憶したこと・タスクが終わったこと・承認が必要なこと・別の会話の返事ができたことは、右下の知らせ（トースト）で出る。Esc は重なり（コマンドパレット・通知の吹き出し・引き出し）を 1 つずつ閉じ、入力欄にいるときだけ返事を止める（日本語の変換中は何もしない）
- ⌘K（Ctrl+K）で、コマンドパレットを開く（ボタンは置いていない。キーボードの無い狭い画面では開けないが、パレットの操作は、タスクのページ・設定 › 見た目・右のパネルにもある）。会話・タスク・スキルを探して開けるほか、新しい会話・いまの動きの開閉・ライト/ダークの切り替え・ワーカーの一時停止と再開・表示の言語の切り替え・各ページを開く操作ができる（↑↓ で選び、↵ で開く）
- タスクの完了・返事待ち・失敗・承認が必要・モデルの不調を、画面の通知（右下のベルの吹き出しと、「すべて見る」で開く通知の一覧）で知らせる。吹き出しの項目を押すと、承認・タスク・会話などの該当の場所へ移り、既読になる。承認が必要なときと返事待ちのときは、ブラウザの通知も出す

### ローカル LLM を使うとき

- 起動時と設定を変えたときに、サーバーから実際のコンテキスト長を確かめ、足りなければ送らずに、数値と直し方を表示する（黙って切り捨てない）
- 実行中も、収まらなければ止め、サーバー側での切り捨ての疑いを見つけたら知らせる
- ツール呼び出しが苦手なモデルのために、本文に書かれたツール呼び出しも拾う

## 必要なもの

- Node.js 24.16 以上（`.ts` をビルドせずにそのまま実行します）
- 使うモデルのどれか
  - Anthropic の API キー
  - ローカル LLM（Ollama・LM Studio・llama.cpp・vLLM など）
  - OpenRouter・OpenAI などの OpenAI 互換 API

## はじめかた

```bash
npm install
npm run build:web           # 画面をビルド（web/dist）
cp .env.example .env        # API キーを書く（Windows は copy）
npm start                   # http://127.0.0.1:4777/ を開く
```

初回の起動で `data/config.json` が作られます。画面の「設定」で、モデルのコンテキスト長の確認結果と直し方が見られます。
ローカル LLM を使うときは、先に下の「[ローカル LLM のコンテキスト長](#ローカル-llm-のコンテキスト長)」を読んでください。

| コマンド | 内容 |
|---|---|
| `npm start` | 起動（`-- --data-dir <dir>` でデータの置き場所を変えられる） |
| `npm run dev` | ファイルを変えると再起動する |
| `npm run dev:web` | 画面だけを開発する（Vite。API は `npm start` のサーバーへ転送） |
| `npm run doctor` | 設定と各モデルの接続を確かめる（問題がなければ終了コード 0） |
| `npm test` | テスト（`node:test`） |
| `npm run typecheck` | 型チェック（サーバーと画面） |
| `npm run check` | 型チェック＋テスト＋画面のビルド |

### ほかの端末から使う

Clive は 127.0.0.1 でだけ待ち受けます。スマートフォンなどから使うときは Tailscale Serve を通します。

```bash
tailscale serve --bg 4777
```

表示された `https://<machine>.<tailnet>.ts.net` を `config.json` の `server.origins` に足し、再起動してください。使える人を絞るときは、その人の Tailscale のログイン名を `server.tailscaleLogins` に足します（空なら、同じ tailnet の人なら誰でも使えます）。

### Linux で常駐させる

[deploy/clive.service](deploy/clive.service) が systemd の設定です（先頭に手順があります）。Clive が書き込める場所をデータのフォルダだけに絞ってあるので、シェルの道具に対する OS 側の閉じ込めにもなります。

## ローカル LLM のコンテキスト長

Clive は毎回、system（ルール・人格・記憶の枠・道具の説明）と会話をまとめて送ります。モデルのコンテキスト長が足りないと、送らずにエラーにします。
必要な長さは、画面の「設定」›「モデルとコンテキスト長」の「必要な長さ」に出ます（`minContext`（既定 65,536）と、system＋道具の説明＋会話の最低量 8,192＋出力の上限、の大きいほう）。目安は最低 32k、道具や記憶を使うなら 64k 以上です。

| サーバー | `providers[].server` | 長さの直し方 | Clive が確かめる場所 |
|---|---|---|---|
| Ollama | （`kind: "ollama"`） | `models[].contextLength` を必要量以上にする（毎回 `num_ctx` として送る） | `/api/show` |
| LM Studio | `lmstudio` | モデルを読み込むときの Context Length を必要量以上にして読み込み直す | `/api/v0/models` |
| llama.cpp | `llamacpp` | `llama-server -c <長さ>`（`-np` でスロットを増やすと、`-c` が分割される） | `/props` |
| vLLM | `vllm` | `--max-model-len <長さ>` で起動する | `/v1/models` |
| TabbyAPI | `tabbyapi` | `config.yml` の `max_seq_len`（と `cache_size`）を必要量以上にして読み込み直す | `/v1/model` |
| そのほか | `generic` | サーバー側で長さを設定する | `/v1/models` に長さが載っていれば使う |

どのサーバーでも、`models[].contextLength` はサーバー側の長さに合わせて書いてください。実際に使うのは「設定値」と「サーバーが報告した長さ」の小さいほうです。

```json
"providers": [
  { "id": "local", "kind": "openai_compatible", "server": "generic", "baseUrl": "http://127.0.0.1:8080/v1", "apiKeyEnv": "LOCAL_LLM_API_KEY", "maxParallel": 1, "timeoutMs": 600000 }
],
"models": [
  { "id": "local-model", "provider": "local", "model": "<サーバーでのモデル名>", "contextLength": 65536, "minContext": 32768, "maxOutputTokens": 8192, "toolMode": "native", "vision": false }
],
"routing": { "chat": ["local-model"], "background": ["local-model"], "retriesPerModel": 2 }
```

- キーが要らないサーバーなら `apiKeyEnv` は書かない。要るなら `.env` に `LOCAL_LLM_API_KEY=...` のように書く
- ツール呼び出しが苦手なモデルは、`toolMode` を `json_fallback` にするか、`maxTools` で渡す道具の数を絞る

## Clive の言語（日本語・英語）

`config.json` の一番上の階層に `language` を書くと、Clive の返事の言語が決まります。

```json
"language": "en"
```

- 値は `"ja"`（日本語）か `"en"`（英語）。書かないときは日本語です。再起動は要りません。画面の「設定」›「見た目」の「表示の言語」（ブラウザに合わせる / 日本語 / English）でも変えられます
- 画面の言語: `language` があればそれに従い、無ければブラウザの言語に従います（「ブラウザに合わせる」は `language` を消すので、返事は日本語のままです）。`language` が無いまま画面が日本語以外になるときは、「Clive の返事も英語にしますか」と 1 回だけ尋ねます（答えはこのブラウザに覚えます。「はい」なら `language` を `en` にします）
- 変わるもの: 返事の言語、ルール（`templates/rules.ja.md` / `templates/en/rules.md`）、SOUL / USER / CURIOSITY の初期値、モデルに渡す決まり文（タスクの実行・振り返り・会話の要約・道具の呼び方の指示、記憶やスキルの見出し）、現在時刻の行
- いつから変わるか
  - 返事の言語の指示は、毎回組み立てる「動的な部分」に入れてあります。だから、すでにある会話にも、言語を変えた次のリクエストから付きます
  - ルールと人格の見出しは、会話の始めに固定されます（上の「大事にしていること」）。そのため英語のルールで始まるのは、言語を変えたあとに始めた会話・タスク・振り返りだけです。前から続く会話は、始めたときのルールのままです
  - 動的な部分の指示だけでは、日本語のルールで始まり日本語の発言が続いている会話は、英語に切り替わらないことがあります（ローカルの Qwen（`qwen3.8-27b`）で、英語に変えたあとの返事が 2 回とも日本語でした）。そこで、**会話の始めに固定したルールの言語（会話ごとに記録します）と、いまの `language` が違うあいだ、毎回**、また、**直前の返事の言語（言語を変えたあとの会話ごとに記録します）といまの `language` が違う最初の実行（始めた言語に戻した直後など。道具を何度も呼ぶ実行なら、終わるまでモデルを呼ぶたびに）に**、モデルへ送る要求の最後のユーザーの発言に「返事の言語がこう変わった」という 1 行の注意を足します。この 1 行は送る写しにだけ足し、会話には保存せず、画面にも出ません。言語を変えていない会話には何も足さず、何も記録しません
  - 同じモデルで、日本語の会話を英語に変えると次の 2 回の返事が英語になり、日本語に戻した最初の返事は日本語で返りました（英語の返事を続けたあとに戻しても同じでした）。ほかのモデルでは確かめていません
- 初期値の写し: 起動のときに、作業フォルダに無いファイルにだけ、いまの言語の版を写します。**すでにある `SOUL.md` / `USER.md` は上書きしません**。言語を変えても日本語のままです
- 英語の初期値は `templates/en/` にあり、`GET /api/templates/en`（ルールと SOUL / USER / CURIOSITY の本文を返す）でも読めます。読むだけで、作業フォルダへ写すのは手で行います（画面の「設定」›「見た目」の「英語の初期値を見る」で読めて、ファイルごとにコピーできます）。英語の版が無いファイルは日本語の版に戻ります
- サーバーが作る文（通知・タスクの経過と理由・繰り返しの説明・道具の結果・承認の依頼の理由・モデルの確認と直し方・返事の失敗と警告・API のエラー）も、作るときの言語で書きます。**言語を変える前に作られた通知や経過は、元の言語のまま残ります**。API のエラー・返事の失敗・モデルの確認には、画面が自分の言葉に訳せるように、変わらないコード（`code`）と差し込みの値（`params`）も付きます（一覧は `map.md`）
- 画面は、コード（`code`）の付く文（API のエラー・返事の失敗・返事の途中の警告・モデルの確認の説明）を、サーバーがどの言語で書いたかにかかわらず、画面の言語で出します（「ブラウザに合わせる」で画面だけ英語のときも、エラーは英語で読めます）。コードが画面の表に無い・値が足りないときは、サーバーが書いた文をそのまま出します
- **英語にしても日本語のまま送る・出すもの**: モデルに渡す道具の説明と引数の説明（道具の仕様の文）、設定の問題の一覧、起動時のエラーとログの行、設定ファイルが壊れたときの文

## 実行前のフック

道具を実行する前に、自分で用意したコマンドに判定させられます（Claude Code の PreToolUse フックと同じ約束なので、Claude Code 用のフックもそのまま使えます）。`config.json` に書きます。

```json
"tools": {
  "hooks": {
    "preToolUse": [
      { "matcher": "shell_run|file_.*", "command": ["node", "/path/to/my-hook.js"], "timeoutMs": 30000, "onError": "deny" }
    ]
  }
}
```

- `matcher` は道具の名前の正規表現。`command` はシェルを通さずに起動する
- 標準入力に `{ "hook_event_name": "PreToolUse", "tool_name", "tool_input", "cwd", "run_id", "conversation_id" }` の JSON が渡る
- 終了コード 2 で拒否（標準エラーの文が理由になる）。0 で終わり、標準出力に `{ "decision": "allow" | "ask" | "deny" | "block", "reason": "..." }`（または Claude Code の `hookSpecificOutput.permissionDecision`）を返すと、その判定になる
- 時間切れ・起動の失敗・ほかの終了コードは `onError`（既定は拒否）。いちばん厳しい判定が使われるので、フックで組み込みの判定（拒否・承認）を緩めることはできない

### 大事にしていること

- **エラー文を返事として残さない**: 返事を作れなかったときは、本文を空のまま失敗として扱い、エラー文が記憶や会話に紛れ込まないようにする
- **黙って切り捨てない**: コンテキストが足りなければ送らずに止め、理由と直し方を出す
- **会話中は system を変えない**: 会話の始めにルール・SOUL・USER・記憶を固定し（プロンプトキャッシュが効き続ける）、書き換えは次の会話から反映する。返事の言語の指示だけは毎回組み立てる動的な部分に入れるので、言語を変えると会話の途中でも次の返事から切り替わる
- **API キーは設定ファイルにも画面にも出さない**: 設定には環境変数の名前だけを書く
- **127.0.0.1 でだけ待ち受ける**: Host・Origin・`Sec-Fetch-Site` を確かめて、ほかのサイトからの操作を断る。この PC の外からは Tailscale Serve のヘッダを求める
- **やることが無ければモデルを呼ばない**: 裏で動く判断はコードで行い、費用がかからないようにする
